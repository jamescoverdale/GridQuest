# GridQuest iOS

Open `GridQuest.xcodeproj` and run the GridQuest scheme. The project currently targets iOS 26.5 and retains the original signing team and bundle identifier.

## First version

- Read-only Apple Health access to workouts and workout routes, requested when the user taps Connect Apple Health.
- Squadra-compatible zoom-14 XYZ squares, with intermediate route crossings calculated in longitude/latitude coordinates.
- Native MapKit map with orange collected squares, optional grid lines, square inspection and a teal outline around one largest filled square.
- The map initially centers on your current location with when-in-use permission. Jump home requests a fresh location; tapping the largest-square statistic frames that square. Ordinary syncs do not move the camera.
- Tapping a square highlights it in blue. Collected-square details show the earliest saved workout date that visited it, including existing imports and older workouts that arrive later. Closing details clears the highlight. Sample dates are illustrative.
- SwiftData storage of each imported workout's accumulated tile set. Repeated syncs update the same workout rather than duplicating it; historical progress survives unavailable/deleted Health routes.
- A sample grid that is separate from persisted Health history. The `--demo` launch argument uses an in-memory database for UI testing.

After connecting once, sync runs automatically when the app becomes active and when a HealthKit route observer reports changes while the app is running. A persisted HealthKit anchored-query token requests only changed route records; successful route IDs prevent rereading GPS on a partial-failure retry. This also catches routes added later to older workouts, which a workout-date cutoff would miss. Each batch's change token and outstanding route IDs are saved together before GPS processing. Each completed import removes its route from that persisted queue in the same save as its tiles. Failed routes can then be fetched directly by ID without replaying history. Automatic retries wait at least a minute after processing and run on a later activation or change notification; manual sync retries immediately. The app does not use a retry timer.

The options menu contains **Sync now** and **Check all Health history**. The latter resets the checkpoint and scans route records again, still skipping GPS for previously imported routes. A small progress indicator and last-updated caption replace the prominent sync button. Background delivery while the app is suspended or terminated is not enabled.

Saved tile sets, workout IDs and dates, processed and pending route IDs, the retry cooldown, sync checkpoint and last-sync time are retained. Raw GPS routes and current device location are processed in memory. HealthKit is read-only. No backend or Strava integration is used.

## Geometry and limitations

The verified Squadra Android APK uses Strava's simplified summary polyline. HealthKit supplies different route samples, so exact historical tile totals are not guaranteed. Squadra database migration is not implemented yet.

Separate HealthKit route objects are never joined. Invalid GPS fixes and gaps over five minutes break the route line; dateline-spanning segments are not bridged across the world. These gap safeguards deliberately differ from Squadra's unrestricted consecutive-point crossing logic. Tile identities and ordinary route geometry match the verified grid.

At wide map zooms, unvisited grid lines are suppressed above 900 visible tiles. Collected tiles remain visible. When multiple equally largest squares exist, the statistics report their common size and the map outlines the first one in row/column order.

Apple keeps Health read permissions private. No available samples may mean no route data, denied access, or workouts without GPS. The app reports that ambiguity rather than claiming it knows access was denied.

## Verification

Unit tests cover the London tile and bounds, longitude wrapping, sparse route crossings, deduplication, largest-square ties, recording gaps, saved-grid reload, sample-data isolation and centering the map on a received location fix. An injected Health source verifies incremental checkpoints, late routes for older workouts, durable partial-failure retries, automatic observation, ignored routes, immediate observer notifications after a partial first sync, retry cooldowns, and quiet automatic failures. Date tests cover late historical imports and reloads; map tests cover selection changes, overlay refreshes and clearing selection. `SquadraRouteFixtures.json` contains 120 deterministic route cases generated by calling the original APK's extracted geometry methods (APK SHA-256: `9baa3ed30a46ad16ead515bca8d0f063c5d5fe7c010e090d0d16e729b270c777`). The test compares exact tile sets against these fixtures.

UI tests exercise the sample grid, returning to onboarding, grid visibility, tapping the largest-square statistic, selecting collected and uncollected squares, the first-collected date, closing selection details and the information sheet with its Squadra credit and website link. They do not access a user's Health history.

Real workout import and the Health permission prompt still need a signed physical-device check with existing GPS workout routes. Simulator sample-grid tests cannot verify that integration end to end.

```sh
xcodebuild -project GridQuest.xcodeproj -scheme GridQuest -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test
```
